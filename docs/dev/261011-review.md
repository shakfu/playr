# Review: playr 0.18.0

2026-10-11, on `dev` at `fec576c`, clean tree. Read-only: no code changed.

Scope: the whole workspace. It excludes `playr-looper`, `playr-dj` and `playr-dsp`, which `docs/dev/261005-review.md` covered; four of that review's `[done]` items were re-checked and hold. The review was split into six areas, each read by one reviewer. Claims marked **verified** were also re-read by hand in the source for this file.

Evidence labels:

- **verified**: traced in the code.

- **measured**: run in a probe program outside the tree (scratchpad only).

- **inference**: not traced or measured.

## Summary

- About 41k lines of source, 34k of tests, about 1000 `#[test]` functions.

- The realtime path is sound and tested. A counting allocator asserts the callback neither allocates nor frees (`crates/playr-core/tests/bus.rs:366`, `:662`).

- The server's perimeter is careful: Host/Origin checks, an HttpOnly SameSite=Strict token, bounded parsing, and a layered `:sql` sandbox.

- The defects are boundary cases: unchecked numeric overflow in the command parser, layout maths at tiny sizes, and one engine path that skips a rule its sibling applies.

- The worst finding is a one-request crash of `playr-server`, item 1.

## Findings

### 1. Command parser panics on huge times (High; measured)

`crates/playr-app/src/command.rs:1168`: `parse_time` rejects NaN, infinity and negatives, then calls `Duration::from_secs_f64`. That panics above about 1.8e19 s.

- Input: `:seek 1e30`, or `18446744073709551615:00`. Reaches `seek`, `mark`, `stop in`, `range`, `in`, `out`, `scrub`, `select`, `move-to`, `tape window`, `dj a seek`.

- `:stop in 1e19` parses, then panics in `Session::sleep_in` (`crates/playr-core/src/session.rs:971`, `Instant::now() + d`).

- Server: `POST /command` with `seek 1e30` runs on the owner thread (`owner.rs:269`), which is `main`. No `catch_unwind`; the process exits. The systemd unit restarts it every 5 s, so repeated requests keep it down. Needs the token, or any LAN host under `--open`.

- A 400k-line fuzz of `parse_typed` found 44 panics, all this cause. `completions` and `Key::parse` survived 300k inputs.

- Fix: `Duration::try_from_secs_f64(..).map_err(|_| bad())`, cap at a day; `Instant::now().checked_add(d)` in `sleep_in`. Test `seek 1e30` in `tests/commands.rs` and the server tests.

Related, Low: `dispatch.rs:1252` (`at + rows`) and `Session::move_in_selection` / `move_in_queue` (`row as i64 + by`) overflow on `:down 9223372036854775807` or `:move +9223372036854775807`. Debug panics; release wraps to row 0. Both actions are web-allowed. Use `saturating_add`.

### 2. Gapless staging ignores the pinned plan (High; verified)

`crates/playr-core/src/audio/mod.rs:1979`: `stage_from` calls `self.backend.negotiate(spec)` unconditionally. `load` (`mod.rs:1340-1345`) keeps the current plan while `holds_bus()` is true.

- Scenario: a DJ deck or the looper is attached, or the master is recording, and the queue crosses 44.1 to 48 kHz. `promote_staged` then `rebuild_output` drops the stream. `Bus::drop` (`bus.rs:314`) drops the record producer, so the master recording ends silently. Attached sources built for 44.1 kHz play into a 48 kHz stream, about 8.8% sharp (inference: playr-dj and playr-looper not re-read).

- Test gap: the fake backend always negotiates the source rate (`tests/common/mod.rs:254`); `tests/bus.rs:433` covers only `Cmd::Play`.

- Fix: share `load`'s rule. Add a fake backend that offers only 48 kHz; it also covers item 9.

### 3. Terminal sampler panics at small sizes (Medium; measured)

- `src/ui/sampler.rs:83` (`braille_rows`): with 0 rows, `dots - 1` underflows. `src/ui/render.rs:278` passes `inner.height.saturating_sub(2)`, which is 0 for a body of 4 rows or fewer. Braille is the default display, so a playing track in the Sampler view in a 3-9 row terminal (a tmux split) panics. The panic hook restores the tty; playback stops.

- `src/ui/render.rs:277`, panic at `:395`: `axis` is `inner.width` long, so 0 at width <= 2, and `axis[0]` panics. All four displays.

- The probe swept TestBackend sizes: 132 panics. No render test is below 40x12 (`tests/render.rs:484`).

- Fix: return early when `rows == 0` or `inner.width == 0`, or a single "terminal too small" guard in `draw`. Add a size-sweep test.

### 4. Prune and nested mount points (Medium; verified)

`crates/playr-core/src/scan.rs:230`, `:262` compute `unavailable` per root: only a root that read wholly empty counts. `db/mod.rs:465` `gone()` / `:488` `prune_missing` then treat every vanished path as deleted.

- Scenario: root `/mnt` holds drives `/mnt/a` and `/mnt/b`; `/mnt/b` is unplugged. A rescan finds files in `/mnt/a`, so `unavailable = 0`. With `auto_prune = true` (`playr-app/src/model.rs:1562`; default false), or a "yes", every `/mnt/b` track goes. `ON DELETE CASCADE` removes playlist entries, marks, loops, hot cues, tempo fixes and grid edits: hand-made data with no other copy.

- `add_root` merging `/mnt/a` and `/mnt/b` into `/mnt` removes the per-root guard they had.

- Fix: count a path as gone only if its nearest existing ancestor is on the same device as the root (`st_dev`), or refuse auto-prune when any directory that held tracks now holds none. Test a nested empty directory under a live root; `tests/scan.rs:576` covers only a wholly empty root.

### 5. The page can start an unbounded recording (Medium; verified)

`crates/playr-server/src/web.rs:94` allows `Mix(_)`, which includes `MixAction::Record` (`crates/playr-app/src/mix.rs:225`). That writes 32-bit float stereo WAV to the samples directory: 1.4 GB/h at 48 kHz, enough to fill a Pi's SD card. `web.rs:28-30` says the page gets "nothing of the sampler or tape". Fix: `Mix(MixAction::Record) => false` ahead of `Mix(_)`, with a case in the allow-list test.

### 6. Library cursor survives reloads by index (Medium; verified)

`Event::Scanned`, `Event::Pruned`, `Event::Analysed` (re-sort via `measure()`) and `Confirm::ForgetRoot` replace `session.tracks()`. `cursors.library` is neither re-anchored nor clamped; `refresh` clamps only the playlists and queue cursors.

- A rescan adding an album that sorts earlier: Enter plays, or the DJ view loads, a different track.

- A prune below the cursor: Activate plays the last track (`Session::play` clamps, `session.rs:528`); Add and Enqueue do nothing, with no message.

- Fix: anchor by path after every reload, as `SetSort` already does (`dispatch.rs` ~633), then clamp.

### 7. WAV recording past 4 GiB (Medium; verified)

`crates/playr-core/src/audio/record.rs:104` writes through hound 3.5, whose RIFF sizes are u32. 32-bit stereo passes 4 GiB at 3h06m at 48 kHz, 46 min at 192 kHz. Release writes a wrapped header; debug panics in the writer thread, so `alive` never drops, `holds_bus()` stays true and `finished()` never returns. Fix: stop or roll over before 4 GiB, or write RF64; lower `alive` from a drop guard.

Related, Low (`record.rs`):

- `:99-110`: the writer reads `slots() == 0`, then `is_abandoned()`. Frames pushed between the two are lost. Read `abandoned` first; break only when abandoned and empty.

- `:104` with `bus.rs:249-256`: after a writer error the bus keeps its record producer, `rec_dropped` climbs each callback, and a later Record replaces the producer on the audio thread, freeing about 768 KB there. Send `StopRecord` on error, and return the old producer through the `gone` ring.

### 8. Analysis worker panics are not contained (Medium; path verified, panic source inference)

`crates/playr-core/src/analysis/mod.rs:522` runs `analyse()` in `thread::scope` workers with no `catch_unwind`. A panic re-raises at the scope join; `session.rs:2279` turns it into an error, so `update_albums` (`:560`) never runs. The file is never stored, stays pending, and panics again on every later `:analyze`. Album loudness and ReplayGain stop updating. Whether Symphonia panics on malformed input is inference. Fix: catch per file and store `Analysis::failed(msg)`.

More generally, `Session::spawn` (`session.rs:1695`) has no catch; only scan, rescan, analyze and prune use `caught`. A panic in plan, write, export, convert, `sql` or open sends no event, and the frontend's pending state stays set. `read_detail` (`:1738`) has no cancel flag, so panning at fine zoom stacks decode threads.

### 9. Resampler latency missing from output marks (Medium; measured size)

`mod.rs:2169-2170` (`halt`), `:2148` (`wrap`), `:2000` (`stage_from`) count `written + carry`, not the frames `Resample` still holds. The probe measured up to 1252 output frames (26 ms) at 44.1 to 48 kHz and 2302 (48 ms) at 0.5x.

- `PlayOnce` under varispeed or on a resampled device: the tail lands after `pause_at`, so the fade-out is cut and the pause clicks; resume plays the held tail first.

- Loop wraps and gapless track changes are reported early by the same amount.

- Fix: expose held latency from `Resample` and add it to the mark.

### 10. OSC flood (Medium; queue verified, effect inference)

`crates/playr-server/src/main.rs:126` uses an unbounded `mpsc::channel()`. OSC is unauthenticated, a bundle expands to about 70 messages per datagram (`osc.rs:212-229`), and the owner runs a full `refresh` and `web::screen` per request. Memory grows and HTTP commands time out at 5 s. OSC is off unless `--osc` is given. Fix: a bounded `sync_channel` for OSC with `try_send` drop, or coalesce queued actions as seeks already are (`owner.rs:213-224`).

Related, Low: the 32 connection slots are taken at accept, before the Host or token check, and held up to 10 s (`http.rs:34`, `:41`, `:101`). One LAN host keeps 32 idle sockets and the page gets 503. Cap per peer IP; shorten the head deadline to about 2 s.

### 11. GUI clones the measures map per frame (Medium; measured)

`crates/playr-gui/src/views.rs:98`: `model.measures_map().clone()`, one entry per analysed track, each frame of Library, Selection or Queue. Probe: 0.32 ms at 5k entries, 12.6 ms at 50k, against a 33 ms frame while playing. `dj.rs:722` already borrows. Fix: drop `.clone()`.

Related, Low: the spectrogram image is rebuilt and uploaded every frame (`crates/playr-gui/src/sampler.rs:1404-1431`), about 1.3 MB at 800x400 (inference). Cache it on (start, per-column, size, region, theme).

### 12. GUI keyboard access (Medium; verified)

- `crates/playr-gui/src/lib.rs:199` closes `Help` and `CommandHelp` on a key, but not `Roots` or `Info`. Keys fall through to the bindings underneath: Esc clears the search, `d` in Playlists asks to delete. The terminal closes all four. Fix: add `Input::Roots(_) | Input::Info(_)` to that arm.

- Tab is bound globally to `view next` (`crates/playr-app/src/keys.toml:26-27`) and `lib.rs:207-212` cancels egui's focus step. So the Forget buttons, the Columns checkboxes and modal buttons are mouse-only. Options: let Tab move focus while a window or modal is open, or use Ctrl+Tab for views in the GUI only. The second breaks key parity between the GUI and the terminal; that is your call.

- Root cause: the routing of keys by input state is duplicated in `src/ui/mod.rs` `on_key` and `playr-gui/src/lib.rs:186-204`, and the two copies have diverged. A `Model::key_for_input(Key) -> bool` in playr-app would give one copy.

### 13. CLI exit codes and pipes (Medium/Low; measured)

- `src/main.rs:521` (scan), `:587` (prune): a missing directory prints "not a directory" and exits 0; `roots rm` exits 1. With no library yet, `scan /nonexistent` also creates an empty library file.

- Broken pipe: `playr search --json track | head -c 10` panics, exit 101. All `println!` in `main.rs` and `analyze.rs`. Fix: `writeln!` to a locked stdout, and treat `BrokenPipe` as success.

- SIGTERM leaves raw mode and the alternate screen on (no handler). Panics are covered by ratatui's hook. If `try_init` fails after raw mode is on, `main.rs:354` returns without restoring.

### 14. CI and release gates (Medium; verified)

- MSRV job (`.github/workflows/test.yml`) runs `cargo check -p playr -p playr-core -p playr-app --all-targets`. Its comment says "every crate but playr-gui". playr-server is never checked on 1.89. The engine crates' tests are not built there. playr-gui's declared 1.95 is never checked. Fix: `--workspace --exclude playr-gui --all-targets --locked`, plus a 1.95 step for playr-gui.

- `--no-default-features` is documented (README) but never built. `opus_reports_cleanly_when_the_feature_is_off` (`crates/playr-core/tests/decode.rs:426`) never runs, because workspace tests unify features.

- The release `check` job runs `make test` on Linux only, without ffmpeg or `PLAYR_REQUIRE_FFMPEG`. So the ffmpeg tests may skip, and a tag does not wait for test.yml on macOS or Windows. Fix: call test.yml from release.yml (`workflow_call`).

- `--locked` appears in release.yml and linux.yaml, not test.yml, msrv or the Makefile.

### 15. ReplayGain peak <= 0 or NaN removes the cap (Low-Medium; verified)

`crates/playr-core/src/gain.rs:83-85`: `Some(_) => f32::INFINITY`. A file tagged `+40 dB` with peak `0` or `nan` plays 100x and hard-clips. Off by default. Fix: treat a non-finite or non-positive peak as unknown (cap 1.0), and clamp the gain to a sane range.

## Low findings by area

**Core audio**

- `output.rs:159-167`: I16/U16 truncate (`as i16`): a 2-LSB dead zone near zero on 16-bit devices. Round; optionally TPDF dither.

- `output.rs:653-656`: pause and resume are hard cuts mid-waveform; the ramp covers volume only.

- `decode.rs:305-312` (inference): packets are interleaved at their own channel count, downstream assumes the stream's first. A mid-stream channel change would swap L/R for the rest of the track under resampling. Reject or remap when a packet's spec differs.

**Core library**

- `analysis/mod.rs:575-584`: `update_albums` reads before writing in a DEFERRED transaction. In WAL mode, a concurrent commit makes the upgrade fail with `SQLITE_BUSY_SNAPSHOT`, which skips the busy handler (inference from [SQLite result codes](https://www.sqlite.org/rescode.html#busy_snapshot)). Analysis runs alongside scans by design. Use `TransactionBehavior::Immediate`.

- `session.rs:1362`: `export_marks` writes `<stem><suffix>` with `fs::write`; two tracks sharing a stem ("01 Intro.flac" in two albums) overwrite each other's `.cue` or labels file.

- `session.rs:2216`: `forget_root` maps any DB error to `NotARoot`. `check_forget` refuses during a scan but not during analysis, which can then write orphan rows.

- `labels.rs:73`: cue `FILE` keeps the `\\?\` prefix on Windows; `m3u::plain` exists for this. `:78` emits `TRACK 100`+, which the format does not allow.

- `m3u.rs:74`: `file:///C:/m/a.flac` becomes `/C:/m/a.flac` on Windows; every entry reads as missing.

**App**

- `action.rs:363-366`: `shift-j` parses as `j`, so `[keys] shift-j = ...` silently rebinds plain `j`.

- `instance.rs:38-45`: if the lock file cannot be opened for writing (a root-owned file left by `sudo playr`), playr runs unlocked with no warning. Fall back to a read handle; warn.

- `persist.rs:58`: history joins on `\n` and assumes none occur; `History::push` and the web path do not strip them.

- `model.rs` `save_values` (~575-590) sets `saved` even when `Session::set_state` (`session.rs:957-960`) failed, so the value is not retried.

- `dispatch.rs:1658` (`[slot - 1]`) and `:1541-1546` (`spans[0]`, `% n`) index without checks; guarded upstream today.

- `dispatch.rs:2030`: `before(f).expect("a track is playing")` re-reads live status after `playing_track()` succeeded (inference: race with Stop).

**Server**

- `http.rs:221`: the Origin check is skipped when Origin is absent. Covered by SameSite=Strict in token mode. Under `--open`, a client that strips Origin allows `text/plain` form CSRF (inference). Require a custom header on POST.

- `http.rs:191-193`: cookies are not isolated by port ([RFC 6265 sec. 8.5](https://www.rfc-editor.org/rfc/rfc6265#section-8.5)), so other services on the same host see `playr_token`. Document it.

- `http.rs:396`: CSP allows `script-src 'unsafe-inline'`. No HTML sink exists today (all tag text goes through `textContent`). Use a hash.

- `packaging/linux/playr-server.service:17-23`: `0.0.0.0:8080`, no sandboxing. Add `NoNewPrivileges`, `PrivateTmp`, `ProtectSystem=strict` with `ReadWritePaths`, `MemoryMax`, `TasksMax`; check which work in a `--user` unit on Pi OS.

- `docs/dev/server.md` says the Pi's unit names both HTTP and OSC; it names only `--listen`.

**GUI**

- `crates/playr-gui/src/fonts.rs:279`, `:298`, `:313`: the fallback can load emoji-bearing faces: Apple Symbols, `seguisym.ttf`, and on Linux whatever `fc-match` ranks first, often Noto Color Emoji. That conflicts with the no-emoji rule and TODO.md:63's claim (font contents inference). Drop Extended_Pictographic codepoints from the query and skip families named "Emoji".

**Build and supply chain**

- Actions are pinned by tag, some by branch (`dtolnay/rust-toolchain@stable`). The release `build` job runs them and uploads the binaries. Pin by SHA; let Dependabot update.

- Release assets carry only a `SHA256SUMS` written by the same workflow; no signature or provenance. `actions/attest-build-provenance` or minisign.

- test.yml fetches BtbN ffmpeg `latest` via `curl | tar`; linux.yaml installs nfpm with `dpkg -i`, neither checksummed. The flatpak container uses a mutable tag with `--privileged`.

- No `rust-toolchain.toml`; a new clippy lint can fail `-D warnings` with no code change.

- `cargo audit` reports 3 unmaintained crates not listed in `.cargo/audit.toml`: derivative and instant (via souvlaki -> zbus 3; no newer souvlaki), ttf-parser (via winit). CI does not run audit. The `paste` ignore still holds.

- `crates/playr-core/src/audio/opus.rs:78`: `unsafe impl Sync for SyncDecoder`, the only unsafe in non-test code. The SAFETY argument depends on opus 0.4's current `&self` methods under a caret requirement. Pin `=0.4.x` or use an uncontended `Mutex`.

- About 60 duplicated crate names (zbus 3+5, zvariant 3+5, getrandom x3); not fixable until souvlaki moves to zbus 5.

**Docs**

- `docs/architecture.md:3` says "current as of 0.12.0". 6 of 64 listed `Session` signatures are stale (`export`, `plan_slices`, `slice_job` take a range; `resume`/`resumable` carry `SavedQueue`). The module lists miss 6 core and 4 app modules. 82 public `Session` functions are unlisted; say the listing is a selection.

- README.md:7 says `playr` and `playr-gui` "have no network code at all". Neither makes requests. Both link zbus on Linux (D-Bus; zbus accepts `tcp:` addresses). playr-gui links `webbrowser`, and the About links open a browser (`lib.rs:687-689`). Reword.

- README.md:803 says ffmpeg 9.0 on every runner; only Linux is pinned.

- README is 87 KB; TODO.md already proposes moving it to `docs/manual.md`.

## Architecture notes

- One code path holds: every frontend action goes through `Model::perform` then `dispatch`. The only direct `session_mut()` calls in the frontends are `set_library_path` at startup.

- `Frontend` has 27 methods, including `session_mut`, and two implementations: `Model` and the test-only `Headless`. It is a test seam, not a boundary.

- `Model` has about 45 fields. `drain_events` is about 250 lines (`model.rs` ~938-1190) and mixes sampler, scan, prune, sql, export and convert. Splitting it per subsystem would follow the existing `tape::poll` / `dj::poll` / `mix::poll` pattern.

- `dispatch` reads live player status, one mutex lock per read, several times per action, not the frame's snapshot. Item 9 of the app list (the `expect` at `dispatch.rs:2030`) follows from that.

- Function hotspots: `playr-gui/src/sampler.rs:178` `show` (630 lines), `dispatch.rs:431` `act` (583), `command.rs:1303` `parse_in` (406).

## Done well

- Realtime safety is tested, not asserted: a counting global allocator around the callback, with sources and while recording. Sources are freed off-thread through the `gone` ring.

- Frames stay whole across the ring on both sides, so an underrun cannot swap channels. Seek uses a generation counter and a Release/Acquire pair, not a device reopen.

- `:sql` sandbox (`crates/playr-core/src/db/sql.rs:88-150`): read-only open, `query_only`, `stmt.readonly()`, an authorizer allowing only temp views and listed functions, plus time, row and size limits. `tests/sql.rs:92-117` tries ATTACH, a CTE bypass, `load_extension` and multiple statements.

- Exports never overwrite: `unused_dir` (`samples.rs:981`) loops on `create_dir`, and failure cleanup removes only what it created. Tag-derived names cannot escape the samples directory.

- Schema: a newer `user_version` is refused before any DDL; migrations run in one transaction; upserts keep track ids, so playlists survive rescans.

- Server: Host allow-list against DNS rebinding, Origin equals Host on POST, HttpOnly SameSite=Strict cookie, 0600 token file created with `create_new`, an early-exit-free comparison, 8 KiB head / 4 KiB body / 32 threads. The page uses only `textContent` for tag text. rosc survived 3M mutated packets. OSC replies go only to `--osc-reply`, so no reflection.

- Confirm payloads carry identity (playlist id, path), not row indices, so a late answer acts on the item asked about.

- `web::allowed` matches every `Action` variant exhaustively, so a new action does not compile until someone decides whether the page may run it. Item 5 shows the cost of the `Mix(_)` wildcard inside that match.

- CI basics: `contents: read` by default, no untrusted `${{ }}` in `run:`, no cache in release builds, tag checked against Cargo.toml and CHANGELOG. `make clippy` matches the lint job exactly.

- The prior review's items 1, 2, 4, 6, 10, 11 and 13 were checked and are fixed, each with a test.

## Suggested order

1. Item 1 (parser overflow) and item 5 (`Mix(Record)`): a few lines each, closes the server crash and disk-fill.

2. Items 3, 11, 12 (first bullet), 13: small, user-visible, each with a test.

3. Item 2 with a rate-refusing fake backend; item 9 rides on the same test fixture.

4. Items 4, 6, 7, 8: data-loss and state cases; each needs a design choice (device check, anchor rule, RF64 or rollover).

5. Item 14 and the supply-chain list, in one CI change.

6. Docs drift.

## Open questions

- Should `auto_prune` exist at all, given item 4? A prune that always asks, and shows per-directory counts, removes the class.

- Is the server's owner thread meant to survive a panicking action? A `catch_unwind` around `perform` would contain future parser bugs, at the cost of continuing with a possibly inconsistent `Model`.

- Tab in the GUI: focus traversal or view cycling (item 12)?
